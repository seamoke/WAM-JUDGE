# RoboTwin Stage-2 One-Shot RFT

This pipeline generates and filters WAM chunks once, then performs full-model
RFT on the union of real and selected pseudo chunks. It does not repeatedly
update the WAM during collection.

## Inputs

Prepare these paths before running:

- prepared RoboTwin Stage-1/Stage-2 split;
- action-visible real dataset generated by the preparation pipeline;
- LingBot-VA Stage-1 WAM checkpoint;
- trained VLAC process critic checkpoint;
- optional holder lease wrapper when the cluster uses a GPU holder.

The provided four-GPU configuration is:

```text
script/configs/robotwin_stage2_one_shot_4xh200.env
```

Edit its absolute paths for the target machine. The 288 GB configuration uses
`INFERENCE_BATCH_SIZE_PER_GPU=8`. Reduce it to 4 if candidate generation runs
out of memory.

## Run

Run directly on a machine without a GPU holder:

```bash
export ROBOTWIN_STAGE2_RFT_CONFIG="$PWD/script/configs/robotwin_stage2_one_shot_4xh200.env"
bash script/run_robotwin_stage2_online_rft_pipeline.sh
```

On a WebAgent Pod with the managed holder, run through the lease wrapper:

```bash
export ROBOTWIN_STAGE2_RFT_CONFIG="$PWD/script/configs/robotwin_stage2_one_shot_4xh200.env"
export CONTROL_FILE=/workspace/webagent-suite/.gpu-guard/webagent-h200-4/pause_until
export LEASE_SECONDS=120
export REFRESH_SECONDS=30
export LINGBOT_SWANLAB_MODE=online
export SWANLAB_MODE=online

bash script/run_with_webagent_holder_lease.sh \
  bash script/run_robotwin_stage2_online_rft_pipeline.sh
```

Do not start the lease wrapper while an unrelated GPU process is running.

## Data Scale

One parameter controls both pseudo and real data scale:

```bash
ONE_SHOT_DATA_FRACTION=1.0   # full: 25,000 pseudo + 60,219 real
ONE_SHOT_DATA_FRACTION=0.1   # test: 2,500 pseudo + 6,022 real
```

The full target remains `ONE_SHOT_TARGET=25000`. Real chunks are selected
deterministically with `BASE_SEED`, so repeated 10% runs use the same subset.
For a test that reuses an existing collection, set:

```bash
ONE_SHOT_COLLECT_ROOT=/path/to/full_run/online/collect
```

The pipeline will finalize the requested pseudo subset from that directory and
start training immediately when enough accepted chunks already exist.

## What Happens

1. Build or verify the action-visible real dataset.
2. Calibrate the kinematic Action Critic from Stage-1 actions.
3. Build dense Stage-2 video contexts.
4. Generate eight WAM candidates for each context.
5. Apply Action Critic and VLAC process-score thresholds.
6. Apply per-context, per-episode, progress-bin, action-diversity, and visual
   quality constraints.
7. Stop collection at the effective pseudo target.
8. Train all selected real and pseudo `F=2` transition chunks for exactly three
   epochs using the official latent and action flow-matching losses.
9. Save the final transformer checkpoint and assemble a complete WAM model.

## Important Parameters

```bash
Q_PER_ROUND=320
CANDIDATES_PER_Q=8
INFERENCE_BATCH_SIZE_PER_GPU=8
VLAC_BATCH_SIZE_PER_GPU=4
TRAIN_BATCH_SIZE_PER_GPU=32
TRAIN_GLOBAL_BATCH=128       # four GPUs
GRADIENT_ACCUMULATION_STEPS=1
ONE_SHOT_TRAIN_EPOCHS=3
MIN_ACTION_SCORE=0.75
MIN_PROCESS_SCORE=5.0
MAX_PSEUDO_PER_CONTEXT=4
ONE_SHOT_MAX_PER_EPISODE=16
```

`TRAIN_GLOBAL_BATCH` must equal:

```text
TRAIN_BATCH_SIZE_PER_GPU * GPU count * GRADIENT_ACCUMULATION_STEPS
```

## Outputs

All artifacts are written below `OUTPUT_ROOT`:

```text
part2/stage1_kinematic_profile.json
part2/stage2_video_contexts.jsonl
online/state.json
online/collect/collect_*/
online/one_shot_pseudo_buffer.jsonl
online/one_shot_pseudo_buffer.summary.json
online/one_shot_train/rft_dataset_report.json
online/one_shot_train/train.log
online/one_shot_train/checkpoints/checkpoint_step_*/
online/final_model/
online/one_shot_complete.json
```

`ONE_SHOT_DATA_FRACTION` defaults to `1.0`. At completion, the trained
transformer is copied into `online/final_model/transformer/`; it is not a
symlink to the training checkpoint. The original checkpoint is retained as a
second recoverable copy.

`state.json` makes collection resumable. Do not delete completed `collect_*`
directories when resuming. SwanLab receives collection metrics, critic score
distributions, data composition, latent/action losses, gradient norm, learning
rate, epoch progress, and selected sample images.

## Verify Completion

For a full run, `rft_dataset_report.json` should contain:

```json
{
  "full_real_items": 60219,
  "real_items": 60219,
  "pseudo_items": 25000,
  "union_items": 85219,
  "num_epochs": 3
}
```

Completion also requires `online/one_shot_complete.json`, the final checkpoint,
and a successful `JOINT_RFT_CHECKPOINT_AUDIT_OK` entry in `train.log`.
